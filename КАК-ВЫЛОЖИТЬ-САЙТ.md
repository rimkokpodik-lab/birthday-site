# 🚀 Как выложить сайт в интернет — пошагово

Инструкция для тех, кто раньше ничего не выкладывал. Всё делается в браузере, без программ и командной строки. Займёт **15–20 минут**.

---

## Сначала — что мы делаем

```
1. Скачать архив  →  2. Выложить файлы на GitHub  →  3. Нажать «деплой» на Render
                                                              ↓
                                   5. Раздать студентам bat  ←  4. Получить адрес https://…onrender.com
```

GitHub — это просто «облачная папка» с файлами. Render — сервис, который берёт папку и запускает её как работающий сайт с адресом в интернете. Платить не нужно.

---

## Шаг 1. Скачайте и распакуйте архив

1. В этом чате, в панели файлов, найдите **`birthday-site.zip`** и нажмите на него → кнопка **«Скачать»**. (Архив не показывается в предпросмотре — браузер сразу предложит сохранить файл.)
2. Откройте папку «Загрузки». Щёлкните по `birthday-site.zip` **правой кнопкой** → **«Извлечь все…»** → **«Извлечь»**.
3. Появится папка **`birthday-site`**. Внутри должно быть:
   - файл `server.js`
   - папка `public`
   - файлы `package.json`, `config.json`, `render.yaml`, `Dockerfile`, `Procfile`
   - папки `bat`, `deploy`, файлы `README.md`, `start.bat`

⚠️ Ничего не переименовывайте и не удаляйте — Render запускает именно `server.js`.

---

## Шаг 2. Зарегистрируйтесь на GitHub

1. Откройте в браузере: **https://github.com/signup**
2. Введите **почту** → **Continue**.
3. Придумайте **пароль** → **Continue**.
4. Придумайте **имя пользователя латиницей** (например `ivanov-teacher`) → **Continue**.
5. Введите ответ на капчу (сложите/выберите картинки) → **Create account**.
6. GitHub пришлёт **код на почту**. Введите его. Если письма нет — проверьте папку «Спам».
7. Если спросят про план — выбирайте **Free** (бесплатный).

---

## Шаг 3. Создайте «папку» для проекта (репозиторий)

1. Откройте: **https://github.com/new**
2. Заполните только одно поле — **Repository name**: `birthday-site`
3. Оставьте выбранным **Public** (бесплатный Render работает только с публичными репозиториями; пароль от кабинета хранится отдельно и в коде его нет).
4. Галочки «Add a README file» и прочие **не ставьте**.
5. Нажмите зелёную кнопку **Create repository**.

Вы увидите пустую страницу с подсказками — это нормально.

---

## Шаг 4. Загрузите файлы на GitHub

1. На этой пустой странице найдите ссылку **uploading an existing file** (мелкий текст в блоке «Quick setup…»). Нажмите её.
   - Если не нашли — откройте напрямую: **https://github.com/ВАШ_ЛОГИН/birthday-site/upload/main**
     (вместо `ВАШ_ЛОГИН` подставьте свой ник).
2. Откройте папку `birthday-site` в Проводнике.
3. **Войдите внутрь неё** и выделите всё содержимое: нажмите **Ctrl + A**.
   - Должны выделиться: `server.js`, `public`, `package.json`, `config.json`, `render.yaml`, `Dockerfile`, `Procfile`, `bat`, `deploy`, `README.md`, `start.bat`, `start.sh`.
   - ❗ Выделяйте **содержимое** папки, а не саму папку `birthday-site` — иначе сайт окажется на уровень глубже и Render его не найдёт.
4. Перетащите выделенные файлы мышкой в окно браузера (или нажмите «choose your files»).
   - GitHub покажет список загружаемых файлов, включая папки `public`, `bat`, `deploy`.
5. Прокрутите вниз → зелёная кнопка **Commit changes**.

**Проверка:** вы вернётесь на страницу проекта, и там должны быть видны `server.js` и папка `public`. Если зайти в `public` — внутри `index.html`, `admin.html`, `style.css`.

---

## Шаг 5. Зарегистрируйтесь на Render

1. Откройте **https://render.com**
2. Нажмите **Get Started** (или **Sign Up**).
3. Выберите **Sign up with GitHub** → **Authorize Render** (разрешить доступ).
4. Если спросят про тариф — выбирайте **Free** / **Individual**.

---

## Шаг 6. Создайте сайт (деплой)

1. В панели Render нажмите **New +** (правый верхний угол) → **Blueprint**.
2. В списке репозиториев выберите **birthday-site** → **Connect**.
   - Если репозитория не видно: нажмите **Configure account** → дайте Render доступ к нему → вернитесь.
3. Render прочитает файл `render.yaml` и покажет план создания — название `birthday-inbox`. Нажмите **Apply** / **Create**.
4. Начнётся сборка. Статус: `Build in progress` → через 2–4 минуты станет **● Live** (зелёная точка).
5. Вверху страницы появится адрес сайта, например:
   **`https://birthday-inbox-xxxx.onrender.com`**
   Скопируйте его — это ваш публичный сайт.

---

## Шаг 7. Зайдите в кабинет и скачайте правильный bat

1. Откройте: **`https://ваш-адрес.onrender.com/admin`**
2. Пароль по умолчанию: **`urok2026`** (в файле `render.yaml` его можно было поменять до деплоя).
3. Вкладка **«Настройки и .bat»**:
   - в строке «Приём файлов» уже должен быть адрес вида `https://ваш-адрес.onrender.com/api/upload`;
   - если поле «Публичный адрес сайта» пустое — впишите туда `https://ваш-адрес.onrender.com`.
4. Нажмите **⬇ Скачать .bat** — готовый файл с нужным адресом внутри.
5. Там же можно переписать тексты внутри bat (блок «Тексты внутри bat-файла») и сохранить.

---

## Шаг 8. Отправьте файл и раздайте bat студентам

1. Запустите скачанный `.bat` у себя и введите тестовые данные.
2. Откройте в кабинете вкладку **«Входящие файлы»** — там должен появиться ваш файл с распознанными ФИО и датой. Значит всё работает.
3. Удалите тестовый файл кнопкой **✕**.
4. Раздайте `otpravka-dnya-rozhdeniya.bat` студентам: в чат группы, на почту, на диск, в LMS.

## ⚠️ Что важно знать про бесплатный тариф Render

| Особенность | Что это значит для вас |
|---|---|
| Сайт «засыпает» после 15 минут без запросов | Первый переход или отправка bat занимает 30–60 секунд. bat сам делает «прогрев» и 3 попытки, поэтому данные не потеряются, но студент подождёт. |
| Хранилище **временное** | Файлы живут, пока сайт работает. После перезапуска/нового деплоя папка `data` обнуляется. **Скачивайте файлы после каждого занятия**: «⬇ Скачать все (.zip)» или «⬇ Все в один .txt». |
| Нужна платная опция для постоянного хранения | План **Starter** (~$7/мес) + диск: в `render.yaml` поменяйте `plan: free` на `plan: starter` и добавьте блок `disk` с `mountPath: /var/data` и переменную `DATA_DIR=/var/data`. Тогда файлы хранятся всегда. |
| Может потребоваться карта | Render иногда просит карту для проверки (на free-плане деньги не списываются). Российская карта может не подойти — тогда смотрите «Вариант Б» ниже. |

## 🧯 Если что-то не работает

**Сайт выдаёт 404 / «Not Found».** Файлы загружены не туда: на GitHub должна быть видна папка `public` и `server.js` в корне репозитория, а не внутри ещё одной папки `birthday-site`. Исправление: удалите репозиторий (Settings → внизу Delete this repository) и повторите шаг 4, выделив содержимое папки через Ctrl+A.

**Render пишет `Build failed`.** Откройте вкладку **Logs** → посмотрите последние строки. Чаще всего это отсутствующий `package.json` — значит файлы загрузились не полностью. Загрузите заново: Add file → Upload files.

**`Unauthorized` при входе в кабинет.** Пароль — `urok2026`, если вы не меняли его в `render.yaml`. Поменять позже: на Render откройте свой сервис → **Environment** → `ADMIN_PASSWORD` → измените → **Save changes** (сервис перезапустится).

**bat пишет «НЕ УДАЛОСЬ ПОДКЛЮЧИТЬСЯ К САЙТУ».** Откройте адрес из bat в браузере. Открывается — значит блокирует антивирус/VPN. Не открывается — сайт спит (подождите минуту и повторите) или адрес в bat устарел (скачайте bat заново в кабинете).

**«Unable to connect to the remote server» на `localhost:3000`.** В bat остался локальный адрес. Скачайте bat заново в кабинете на Render — в нём будет `https://…onrender.com`.

**Файлы пропали.** Сработал перезапуск на бесплатном тарифе (см. таблицу выше). Скачивайте архив после каждого занятия или перейдите на платный план с диском.

## 🇷🇺 Вариант Б: если Render не подходит (карта, скорость, «засыпание»)

Нужен российский хостинг или постоянная работа — подойдёт любой **VPS** за 200–400 ₽/мес (Timeweb Cloud, Beget, REG.RU, aeza и т. п.). Файлы и настройки те же.

Кратко (команды вводятся в SSH-консоли сервера, которую даёт хостинг):

```bash
# 1. Node.js
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs

# 2. Загрузите папку проекта на сервер (через файловый менеджер панели или scp),
#    затем в папке проекта:
cd /opt/birthday-site
sudo npm i -g pm2
ADMIN_PASSWORD=вашпароль PUBLIC_URL=http://ВАШ_IP:3000 pm2 start server.js --name birthdays
pm2 save && pm2 startup
```

Сайт откроется по адресу `http://ВАШ_IP:3000` и будет работать круглосуточно, файлы хранятся на диске сервера (`data/`).

Для красивого адреса и HTTPS: привяжите домен к серверу и поставьте nginx как reverse proxy + бесплатный сертификат Let's Encrypt (certbot). Если решите идти этим путём — скажите, дам готовый конфиг nginx и пошаговые команды.

## 💻 Вариант В: без хостинга вообще (для работы в одном классе)

Если все студенты в одной сети (один компьютерный класс, один Wi-Fi):

1. Запустите `start.bat` на своём компьютере.
2. Узнайте свой IP: `ipconfig` → строка **IPv4-адрес**, например `192.168.1.50`.
3. В кабинете → «Настройки и .bat» → «Публичный адрес сайта»: `http://192.168.1.50:3000` → скачайте bat.
4. Разрешите Node.js в брандмауэре Windows, когда появится запрос.

Сайт будет доступен, пока ваш компьютер включён. Из дома студенты к нему не подключатся — для этого нужен Вариант А или Б.
